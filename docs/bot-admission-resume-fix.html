Root-cause chain

16K actor arrays saturate the shared DMA link
  → admission probe scatter only lands ~1-3 of 43 chunks per pass
  → slicePartial=true → admitRingAdvanceOk=false  (ring never advances)
  → next pass restarts the SAME slice from row 0
  → zero-buffer rows (never scattered) still get fname-probed
  → mass negative-memoization → permanent blindness
  → cache:0, drawing:0

B4 (already in RobotList.cpp) fixes the scan restart with s_admitResumeRow, deterministic bandRows order, and processing only freshly-scattered rows. Two gaps remain:

  • Frontier captured before screening. A 40 ms screening / 60 ms serial-verify break after a full scan resets resume to 0 → whole band re-scattered next pass → livelock on slice 0 even with B4 compiled.
  • Verify stage sets slicePartial=true. Ring advancement is frozen by a stage that must not gate discovery.

Stage 1 — B5: monotonic frontier (resume from the screening frontier)

File: Project/Functions/RobotList.cpp

The resume cursor must reflect how far the band was fully consumed (scattered and screened), not only how far it was scattered. Steps:

  • Move the frontier bookkeeping after the screening loop. Keep scatteredEnd = min(base, probeRows.size()) and the distance-sort gate as-is. Capture processEnd (row index the 40 ms screening budget reached).
// B5: resume from the SCREENING frontier — monotonic progress. Rows in
// [processEnd, scatteredEnd) were scattered but not screened; they are
// re-scattered next pass (cheap, chunked) and cannot be lost.
const size_t prioCount = prioRows.size();
const bool sortedSweep = scatteredEnd >= probeRows.size();
const bool consumedAll  = sortedSweep && processEnd == scatteredEnd;
if (consumedAll) {
    s_admitResumeRow = 0;          // full band consumed → advance ring
} else if (sortedSweep) {
    s_admitResumeRow = 0;          // distance-sorted order ≠ band order; replay
    slicePartial = true;
} else {
    const size_t bandProcessed =
        (processEnd > prioCount) ? (processEnd - prioCount) : 0;
    s_admitResumeRow =
        resume + (std::min)(bandProcessed, bandRows.size() - resume);
}

Ring gate unchanged (admitRingAdvanceOk = !slicePartial) — now only scatter/screening partiality stalls it, and every partial state persists real progress.

Stage 3 — Mirror B5 to the player ring (EntityList)

File: Project/Functions/EntityList.cpp

The player ring is pre-B4: unordered probeSet iteration, no resume frontier, screening over all rows (zero-buffer rows beyond scatteredEnd too), distance-sort gated only on !probeRows.empty() — frozen at slice 0 on Riventides.

  • New static s_playerAdmitResumeRow (cleared in ringReset). A separate verify backlog is not needed here — the serial PS-chase/fname stage is the screening loop, so the processEnd frontier covers partial passes.
  • probeSet → deterministic bandRows + prioRows (band math, dedup, prio cap, prio rows lead — same as B4 bot path). PlayerScanNegMemoHit moves into the screening loop so probeRows stays a 1:1 projection of prio+band (frontier stays positionally exact).
  • Compute scatteredEnd after the chunked scatter; gate the distance-sort on scatteredEnd >= probeRows.size().
  • Screen loop → for (size_t ri = 0; ri < scatteredEnd; ++ri) with fresh 40 ms budget, capture processEnd, then the same B5 frontier + slicePartial rule.
