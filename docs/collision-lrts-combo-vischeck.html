Stage 1 — CollisionMirror module (port, offsets corrected)

New file: Project/Functions/CollisionMirror.h/.cpp — port the UC pipeline with offsets replaced by the table above.

  • Read world triangles per StaticMeshComponent: convex (VertexData + IndexData → world via comp transform), boxes (12-tri), spheres (8-tri octahedron), sphyls (box approx). Level-set elems skipped (no portable layout). Every read capped + validated like the probe.
  • KD-tree over world triangles (leaf ≤ 8 tris, median AABB split).
  • Background rebuild: static-mesh roots within 60000 units, dedupe by mesh+transform fingerprint, rebuild on move > 3000 units or 20s. Publish under mutex; queries try_lock the pointer and raycast lock-free — paint never blocks (same rule as the radar fix).
  • is_visible(from,to): segment ray vs KD-tree (Moller–Trumbore, t_max=1). No tree yet → visible (fail-open).

Stage 2 — Debug visualization (the part you asked for)

New vars collision_debug_draw + collision_debug_rays (default off), checkboxes in the LRTS menu tab.

Blocks

  • Every triangle in the published tree, projected via ProjectWorldLocationToScreen and drawn with g_renderQueue.addLine (3 edges per tri).
  • Gray/white for normal geometry, red for the triangle a ray actually hits (tagged during the LOS pass).
  • Clamp to triangles within ~2000 units of the camera.

Rays

  • For each bot/player the ESP processes: camera→target line — green = visible, red = blocked.
  • Queued to g_renderQueue at verdict time, flushed on paint — zero new paint-path work.

This stage doubles as the validation harness: with debug on you can see whether the tree matches the map (blocks on walls) and whether rays flip at real occlusion edges — before any verdict is trusted.

Stage 3 — LRTS + collision voting (the "real vischeck")

Hooks into the existing per-entity chain where actor.isVisible is set. LRTS primary, collision as fallback + tie-breaker:

LRTS verdictCollision rayFinal
VisibleblockedOccluded ← stale stamp behind walls (30–70s wasp case)

OccludedanyOccluded ← renderer truth wins
UnknownblockedOccluded ← collision fills LRTS gaps

Unknownno tree (warmup)Visible ← fail-open

Feeds the same VerdictSmoother (2-check occlusion confirm, Unknown holds verdict) so the combo inherits the flicker-free behavior already in place. The LOS raycast is pure math on cached triangles — no DMA in the query; the rebuild stays on the worker, throttled by movement/interval.

Stage 4 — Validation gates (before trusting it)

  • Debug-on visual: blocks on walls/floors, rays red crossing a wall, green in open air.
  • Wall-pop test: strafe behind a wall — box hides fast, no ghost flicker.
  • Red/green split matches what you see on screen.
  • Tree stats readout in menu: tri count, mesh count, rebuild time, query time.

Out of scope (deliberately)

  • Level-set / tapered-capsule geometry (no portable layout; the 101 convex hulls carry the weight).
  • Persisting geometry across raids (rebuild is cheap).
  • Dynamic occluders (doors/vehicles) — static meshes only, same as the UC source; LRTS covers the dynamic gaps.
