Why the WorldMirror found 0 actors, what five other games do for external visibility, and the staged fix. Sources: zarboz UE4 PhysX writeup (Feb 2026), junglepuppy Tarkov PhysX recreation, Arc Raiders obstruction thread (UC), PUBG reversal thread.

1 — The wrong conclusion, corrected

✗ Earlier claim: "No PhysX DLLs loaded → game uses Chaos, mirror must be rewritten."
Why it was wrong: the module list was taken from ArcRaiders.exe on this PC — that is our DMA client, not the game. The game runs on the target machine; its modules are invisible here. Meanwhile help.txt contains Gu::HeightField (PhysX3Common_x64.dll, IDA-verified) structures — PhysX 3.4 is statically linked into the game.
✓ Community confirms: jouh + zarboz on UC (Feb 2026): "the game uses physx not chaos, you can make perfect vis check pretty easily." The PhysX mirror approach is correct — the discovery is what's broken.

2 — Root cause of the 0-actor failure

a) Wrong object accepted as PxScene. UWorld+0x4E0 is labeled PHYS_SCENE in help.txt but the note says PhysicsField — the Chaos-style field system, not FPhysScene. Our LooksLikePxScene() only checked "vtable is a usermode address" — everything passes that.
b) Back-pointer validation not implemented. zarboz's check — FPhysScene+0xA0 == UWorld — is documented in our own physx-mirror-plan.md but never coded into the combined discovery path.
c) Sig-scan loses to hints. 48 8B 81 ?? ?? ?? ?? C3 scan exists, but hint offsets are tried first and a garbage candidate at 0x4E0 wins.
d) Garbage in, garbage out. The NpScene scanner then read 1MB of the wrong object: 85K read failures, 2551 fake candidates, concreteType values 0 / 65 / 44768 instead of 6 / 7. The scanner itself is fine — it was fed a fake scene.

4 — Two data paths, one query engine

Path A: PhysX NpScene (primary) UWorld → FPhysScene (validated: +0xA0 back-ptr == UWorld) → PxScene +0xB0 (vtable must be in a module range) → NpScene scan → PxRigidActor[] → shapes → geometry Path B: FKAggregateGeom (fallback, zero PhysX internals) Level actor → StaticMeshComponent.StaticMesh 0x728 → StaticMesh.BodySetup 0x1F0 → BodySetup.AggGeom 0xB8 (KSphereElem / KBoxElem / KSphylElem / KConvexElem) → dedupe by StaticMesh asset ptr, instance transform per component ↓ both paths existing local grid broadphase + prim raycast + LineOfSight() — already built
All Path B offsets are already verified in our own SDK dump (CL-1341255): StaticMesh 0x728, BodySetup 0x1F0, AggGeom 0xB8 (size 0x78), elems at 0x0 / 0x10 / 0x20 / 0x30. If NpScene offsets ever drift again, Path B keeps visibility alive.
